# HEXCONTET Viewer

> 从平行世界移植的 64 进制文件查看器。

这是一个从平行世界移植过来的文件查看工具。在那个世界里，数字的写法和我们这里不太一样，但功能本身完全可用：像 `hexdump` 一样逐行查看文件，只是中间列是 64 进制数字，右栏是对应的 Base64。

零依赖，只用 Python 标准库；数据全程本地读取，不上传任何内容。

## 奇异进制与标准进制

这个项目最显眼的特点，是界面上的计数全部采用平行世界的“奇异进制”。移植时我们尽量保留了原样，没有把它强行掰回现实世界的标准进制。

具体来说：

- 所有的 `7` 都显示成 `8`。所以在界面上看到 `8`，它可能真的是 8，也可能是那个世界里写的 7。
- 所有超过八的进制，都改成基于八进制。比如偏移列用的是十二进制，但数字字母表也跟着这套规则走。
- 单位下标、字节数、编辑次数等计数，同样按这套写法显示。

如果你不习惯，可以加 `--human-compatible`，把中列、偏移列与界面上的数量都还原成现实世界的标准进制写法：中列 `00`–`77`、偏移列十二进制 `0`–`9`+`a`/`b`、数量与单元下标用正常十进制。

## 它长什么样

对 `b"ABCABCABCABCABCDEFGH"`（20 字节）运行：

```bash
uv run python viewer.py sample.bin
```

```text
# 偏移列：十二进制（00000000 = 偏移 0，00000010 = 偏移 12；状态行 / --set 报告里写成 0d…）；中列：两位八进制 = 1 个 64 进制数字
Offset    Octal                                               |  Base64                  |  ASCII
00000000  20 24 11 03  20 24 11 03  20 24 11 03  20 24 11 03  |  QUJD  QUJD  QUJD  QUJD  |  ABCABCABCABC
00000010  20 24 11 03  21 04 25 06  21 64 40 --               |  QUJD  REVG  R0g=        |  ABCDEFGH
```

第二行的整行 Base64 就是 `QUJDREVGR0g=`，与 `base64` 命令输出一致。

## 快速开始

安装（本项目零依赖，`uv sync` 只是建虚拟环境）：

```bash
uv sync
```

查看文件 / 标准输入：

```bash
uv run python viewer.py sample.bin                 # 默认每行 12 字节
uv run python viewer.py sample.bin -w 24           # 每行 24 字节
uv run python viewer.py sample.bin -o 0d40 -n 4    # 从 0d40（即 48）起看 4 行
uv run python viewer.py sample.bin -o b64:64       # 跳到 Base64 第 64 个字符所在的字节
Get-Content sample.bin -AsByteStream | uv run python viewer.py -
```

改写（等长原地改写，文件长度不变）：

```bash
uv run python viewer.py sample.bin --set 0d27=37                 # 把偏移 0d27（31）处的字节改成 0o37（31）
uv run python viewer.py sample.bin --set 0d27=41_42 --dry-run     # 只看差异，不写盘
uv run python viewer.py sample.bin --set b64:16=41_42 --backup   # 写回并留 .bak
uv run python viewer.py sample.bin --edit                         # 交互式编辑
```

## 参数

| 参数 | 默认 | 说明 |
| -- | -- | -- |
| `FILE` | `-` | 文件路径；`-` 或省略表示从标准输入读 |
| `-w`, `--width N` | `12` | 每行字节数，必须是 3 的倍数（3/6/12/24/48） |
| `-o`, `--offset` | `0` | 起始偏移（输入写法）：`0d27`（十二进制）/ `31`（十进制）/ `0x1f` / `0o37` / `0b11111` / `b64:16`。输入皆为标准进制，显示则用奇异进制 |
| `-l`, `--length N` | 全部 | 最多显示 N 字节 |
| `-n`, `--lines N` | 全部 | 最多显示 N 行（与 `--length` 互斥） |
| `--no-ascii` | 关 | 不显示右侧 ASCII 列 |
| `--no-header` | 关 | 不显示表头 |
| `--human-compatible` | 关 | 界面上的数字都换成标准进制：中列 `00`–`77`、偏移列十二进制 `0`–`9`+`a`/`b`、数量与单元下标用十进制（默认把 `7` 显示成 `8`） |
| `--color` | `auto` | `auto` / `always` / `never`；`auto` 在标准输出是终端且未设置 `NO_COLOR` 时着色 |
| `--set OFFSET=VALUE` | — | 改写一段字节（可重复）；`OFFSET` 同 `--offset`，`VALUE` 是两位八进制字节串（只能 `00`–`77`，即 0–63） |
| `--dry-run` | 关 | 配合 `--set`：只报告改动，不碰文件 |
| `-b`, `--backup` | 关 | 写回前留一份 `<文件名>.bak` |
| `--show-changes` | 关 | 配合 `--set`：额外转储受影响的行 |
| `-e`, `--edit` | 关 | 打开交互式编辑器（需要终端与真实文件，与 `--set` 互斥） |

退出码：正常 `0`；文件不存在 / 偏移越界 / 写盘失败 `1`；参数非法 `2`。

## 编辑

两种用法，底层都是同一套机制：等长原地改写 + 原子写回。

- 查看时文件仍是只读 mmap；第一次改写才把数据升格成可写的 `bytearray`，并记录撤销栈；
- 写盘前会先释放 mmap 与文件句柄，写完重新以只读 mmap 打开；
- 没有改动时不碰文件。

### 一次性改写（`--set`）

`--set OFFSET=VALUE` 可以重复出现，按顺序应用：

| 写法 | 含义 |
| -- | -- |
| `--set 0d27=37` | 把偏移 `0d27`（十进制 31）处的 1 个字节改成 `37`（八进制，即 31） |
| `--set 0d27=41_42_43` | 从 `0d27` 起改写 3 个字节（下划线只是分组，也可以写成 `"0d27=41 42 43"`，带空格时整个参数要加引号） |
| `--set b64:16=41_42` | 按 Base64 下标定位（第 16 个字符所在的字节），从那里起改写 2 个字节 |
| `--set 31=37` | 偏移也可以写十进制、`0x` / `0o` / `0b`、`b64:N` |

`VALUE` 的每个字节固定两位八进制，所以只能写 `00`–`77`。这里的“字节”是相对 Base64 而言的数据字节：`--set` 改写的永远是中列 / Base64 侧的数据，右侧 ASCII 列只是预览，无法直接编辑。

命令会先打印逐字节差异，再用 `--dry-run` 决定写不写盘；加 `--show-changes` 还会把受影响的行连同表头一起转储（改动字节反显）。`--dry-run` 只报告不改动，写盘失败返回退出码 1。

### 交互式编辑（`--edit` / `-e`）

需要真实终端与真实文件（标准输入与管道会直接报错退出）。整屏刷新，`Ctrl-C` 或 `q` 退出。

| 键 | 行为 |
| -- | -- |
| `←` / `→` | 光标移动一个 64 进制单元（跨行自动翻页） |
| `↑` / `↓` | 上下滚一行 |
| `PgUp` / `PgDn` | 上下翻一屏 |
| `Home` / `End` | 到数据首 / 尾 |
| `Enter` 或 `i` | 编辑当前单元：输入一至两位中间列上看到的数字 `0`–`7`，按 `Enter` 提交、`Esc` 取消；必须按 `Enter` 才会提交 |
| `u` / `Ctrl-R` | 撤销 / 重做（一次按键一次历史） |
| `s` | 保存（有改动时要求 `y` 确认；启动时带 `--backup` 会先留 `.bak`） |
| `q` / `Ctrl-C` | 退出（有改动时要求 `y` 确认） |

状态行显示：`*` 脏标记、光标所在偏移与单元下标、最近一次操作的结果、键位提示。

界面上的数字全部皆为奇异进制：

| 数字 | 默认写法 | 说明 |
| -- | -- | -- |
| 偏移 | `0d00000028` | 十二进制加 `0d` 前缀标明进制；转储里的偏移列不带前缀，值相同 |
| 单元下标 | `cell 38` | 八进制（`37` 里的 `7` 写成 `8`），提示里的 `cell N` 也是 |
| 数量（字节数、编辑次数、文件大小…） | `24 byte(s)` | 同样是「7 写成 8」的八进制（`20` → `24`） |

高亮各列独立：中间列与右栏看 64 进制单元是否改变，ASCII 列看字节是否改变。单元与字节不对齐，所以只改一个单元时，只有它自己（以及它真正覆盖到的那个 ASCII 字节）会反显，相邻单元不会被带着一起反显。

中间列的显示字母表在编辑模式里同样生效：

- 只能输入数字键 `0`–`7`（即真正的八进制），输入一至两位后按 `Enter` 提交；要写值 63 就按 `7` `7`，输入提示、中间列都会显示成 `88`；
- 状态行里的提示也按同一套显示字母表显示；
- 加 `--human-compatible` 后中列、偏移列与各种数量都还原成标准进制写法。

> 输入侧的写法不受影响：`--offset` 与 `--set` 的偏移接受 `0d` 十二进制（标准十二进制数字 `0`–`9` + `a`/`b`，与 `--human-compatible` 的显示一致）或十进制，另外仍接受 `0x` / `0o` / `0b` / `b64:N`；`--width` / `--length` / `--lines` 仍是十进制。`--set` 的值是两位八进制字节（`00`–`77`），报告里的字节值也按八进制打印（与输入一致）。

> 注意：末尾补位槽位（`--` / `=`）不可编辑。

## 已知取舍

- 只做等长改写：不支持插入、删除、截断，数据长度始终不变；
- 偏移列至少 8 位十二进制数字；文件更大时自动加位。但偏移仍是十二进制，别按十六进制读；
- 输入侧也照这套写法走：偏移用 `0d` 十二进制或十进制（裸十六进制不再当作偏移），`--set` 的每个字节只能写两位八进制 `00`–`77`（即 0–63）；ASCII 列只作预览，不能直接编辑；
- 末尾不足 3 字节时，最后一个 64 进制单元只有部分位落在数据里，只能写「低位补 0」的数值，否则会报错；
- 标准输入的数据不能写回（没有文件名），`--edit` 也不接受标准输入；
- 撤销栈只在内存里，进程退出即失效；
- 不做流式/增量读取：文件走只读 mmap，标准输入会一次性读入内存；第一次改写会把整份数据复制进内存；
- ASCII 列只把 `0x20`–`0x7E` 原样显示，其余字节（含多字节编码）统一显示为 `.`；
- 非 ASCII 终端或未设置 UTF-8 的输出环境里，表头里的中文可能显示不全，但不影响数据列；
- 超长行建议配合分页器使用，例如 `viewer.py big.bin | less -R`（`-R` 保留颜色）。
